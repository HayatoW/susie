# ブリーフ

susie は、 Hayato が自分で使う Web ブラウザです。 UI は GPUI で作ります。

## 目的

Hayato は、コードレビューをしなくても AI エージェントの成果物を信頼できる開発を練習します。題材は、 GPUI で、 Hayato がほしい Web ブラウザを作ることです。

## 信頼の根拠

成果物を信頼する根拠は、次の 5 つです。

- テストと形式検証
- 状態遷移図
- 録画とスクリーンショット
- 計測した数値
- Hayato 本人の理解

Hayato が成果物を信頼するのは、この 5 つがリポジトリにあるときです。

## 任せること

実装、テスト、検証、調査、ドキュメントはエージェントに任せます。判断、理解、コントロールは Hayato が持ちます。

方針、大きな設計の分かれ道、マージ、リリースを決めるときは、エージェントが選択肢、おすすめ、理由を出します。決めるのは Hayato です。

## 置き場所

コードも、信頼の根拠も、 Cursor Origin のこのリポジトリ 1 つに置きます。ブリーフは `docs/brief.md` 、タスクは `docs/board.md` 、決定記録は `docs/decisions/` です。決めた 3 件は、 [CEF をページの中身にする](decisions/0001-cef.md) 、 [最初の OS は macOS にする](decisions/0002-macos-first.md) 、 [リポジトリは Cursor Origin に置く](decisions/0003-cursor-origin.md) です。

## 作るもの

ページの中身は Chromium です。 CEF を、 `cef-rs` の offscreen rendering 経由で組み込みます。

感触の目標は、 Ghostty のような軽快さです。測るのは起動時間、入力の遅れ、スクロールの fps です。目標の数値は、最初に動くものができてから Hayato が決めます。

UI はデザインの原則に従います。画面に出すものを絞り、同じ操作には同じ名前を使い、認知負荷を低くします。

最初の OS は macOS です。次に Linux (Omarchy) へ進み、 Windows はその後です。

## 当面やらないこと

次の項目は TODO です。 `docs/board.md` に同名の項目があり、 Hayato が範囲を変えるまで着手しません。

- JavaScript エンジンやレンダリングエンジンの自作
- 既存サイトとの完全な互換性
- 拡張機能、同期、パスワード管理
- Windows 対応
- 他人への配布や公開

## ブラウザに必要なもの

次の 11 個が、ブラウザに必要なものです。

1. ウィンドウと描画の土台です。 GPUI がウィンドウを開き、 CEF が描いた画素を表示します。
2. 入力の受け渡しです。キーボード、マウス、スクロール、 IME をページへ届けます。
3. ページの中身です。 HTML と CSS と JavaScript の実行は CEF が担当します。
4. ナビゲーションです。 URL を開き、前のページへ戻り、次のページへ進み、再読み込みします。
5. タブとウィンドウです。複数のページを並べて切り替えます。
6. ブラウザの基本操作です。アドレスバー、戻る、進むのように、人がページを移動するために触るものです。
7. 保存するデータです。履歴、ブックマーク、設定のように、終了したあとも残すものです。
8. 操作体系です。ショートカット、コマンドパレット、設定ファイル、 CLI を含みます。
9. プロセスと安定性です。ページのプロセスが落ちても、ブラウザ自体は動き続けます。
10. 計測と検証の仕組みです。起動時間、入力の遅れ、スクロールの fps 、テスト、形式検証、状態遷移図、録画、スクリーンショットを含みます。
11. ビルドと配布です。 Hayato が使う OS で、同じソースからビルドします。

リスクが高いのは 1 と 2 と 9 です。 10 は信頼の根拠なので、最初のアプリから入れます。最初の一歩に入るのは、自動テスト、起動時間、描画の fps 、録画、スクリーンショットです。状態遷移図と形式検証も 10 の一部です。入力、ナビゲーション、プロセスのように状態を持つ部分を作るとき、その部分へ入れます。

## 最初の一歩

macOS で、 CEF が描いた 1 ページを GPUI のウィンドウに表示します。そのページでスクロール、クリック、文字入力ができます。起動時間と描画の fps は、自動で記録されます。完了は、録画と、その起動で記録した数値を一緒に見せたときです。

タスクの分割と受け入れ条件は `docs/board.md` にあります。 IME での日本語変換は最初の一歩の外で、地図の 2 に残します。最初の一歩が `complete` になってから、小さなタスクに分けてボードへ追加します。
