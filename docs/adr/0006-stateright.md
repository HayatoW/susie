# 状態を持つ部分の検査には stateright を使う

日付は 2026-11-22 です。決定者は Hayato です。状態は採用です。

ナビゲーション、入力、プロセスのように状態を持つ部分は、 Rust の [stateright](https://github.com/stateright/stateright) でモデル検査します。アプリの実行には使いません。

## 選択肢

1. TLA+ と TLC です。仕様を実装と別の言語で書き、 TLC が状態を探します。
2. stateright です。 Rust の型でモデルを書き、同じプロセスの中で状態を探します。
3. 検査器をこのリポジトリに自作します。幅優先探索と性質の判定を、依存なしで書きます。

## 理由

選んだのは stateright です。

検査は `cargo run -q -p nav-model` の 1 コマンドで終わります。ワークスペースの `cargo test` が同じ検査を実行するので、 `.github/workflows/rust.yml` を変えずに CI へ入ります。入力やプロセスのモデルも、同じ道具の別クレートとして足せます。

TLA+ と TLC は、仕様が実装から分かれます。その代わり JVM と TLA+ のツールが要ります。今の CI は cargo だけなので、そこへ Java を足すには `rust.yml` を変えることになります。状態を持つ部分がこれから増えるので、実行の土台は cargo の 1 つにします。

自作の探索は、依存を増やしません。一方で、探索の抜けと、モデルの欠陥が区別しにくくなります。検査の道具は、ナビゲーションだけで終わらせないので、自作しません。

## 範囲

stateright を使うのは、モデル検査だけです。 `crates/app` と `crates/engine` からは参照しません。

ナビゲーションの振る舞い自体は、この ADR ではなく [ナビゲーションの状態遷移](../evidence/S10/navigation.md) が決めます。振る舞いを変えるときは、図とモデルを一緒に変えます。
