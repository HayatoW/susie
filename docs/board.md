# タスクボード

このボードが、今の作業の一覧です。地図の全体は `docs/brief.md` にあります。最初の一歩以外は、着手するときに小さなタスクへ分けて、このボードへ移します。

## 状態

タスクの状態は、各タスクの状態の行にだけ書きます。状態別の欄には並べません。

- `ready` は、着手してよいタスクです。
- `working` は、いま着手しているタスクです。
- `blocked` は、先に必要なものが足りず止まっているタスクです。
- `awaiting approval` は、 Hayato の判断を待っているタスクです。
- `complete` は、受け入れ条件を満たし、証拠がリポジトリにあるタスクです。

エージェントは、着手するときにそのタスクの状態の行を `working` に書き換えます。受け入れ条件を満たし、証拠を `docs/evidence/` へ置いてから、その行を `complete` に書き換えます。方針、大きな設計の分かれ道、マージ、リリースは、その行を `awaiting approval` に書き換え、選択肢、おすすめ、理由を添えます。節は動かしません。

### S04 フィクスチャを GPUI のウィンドウへ表示する

状態は `complete` です。

先行は S02 と S03 です。

S03 のフレームを、 S02 のウィンドウの中に表示します。 Linux では CPU で画素をコピーして表示します。計測する起動時間と描画の fps は、このコピーを含んだ値です。

起動時間は、プロセス開始から最初のフレームまでのミリ秒です。描画の fps は、最初のフレームから 1 秒のあいだに出したフレーム数です。起動時間を `startup_ms` 、描画の fps を `fps` として、 `docs/evidence/metrics.jsonl` に 1 行ずつ残します。数値の良し悪しは判断しません。目標値は、最初に動くものができてから Hayato が決めます。

受け入れ条件:

- Linux で、フィクスチャの `susie-top` が GPUI のウィンドウの中に見えます。
- その画面のスクリーンショットが `docs/evidence/S04/` にあります。スクリーンショットは、クラウドの Linux VM 上のコマンドが自動で撮ります。
- 実際にアプリを起動すると、 `docs/evidence/metrics.jsonl` に、その起動で計った `startup_ms` と `fps` の 1 行が増えます。
- 表示経路は CPU コピーのままにします。別の経路へ変えるときは、タスクを `awaiting approval` にし、選択肢、おすすめ、理由を Hayato に出します。
- 検証は、クラウドの Linux VM 上で、人の操作なしに実行できるコマンドです。証拠はリポジトリに残ります。
- 完了報告に、スクリーンショットと、その起動の計測値が付きます。
