# タスクボード

このボードが、今の作業の一覧です。地図の全体は `docs/brief.md` にあります。最初の一歩以外は、着手するときに小さなタスクへ分けて、このボードへ移します。

## 状態

- `ready` は、着手してよいタスクです。
- `working` は、いま着手しているタスクです。
- `blocked` は、先に必要なものが足りず止まっているタスクです。
- `awaiting approval` は、 Hayato の判断を待っているタスクです。
- `complete` は、受け入れ条件を満たし、証拠がリポジトリにあるタスクです。

エージェントは、着手するときにそのタスクを `working` へ移します。受け入れ条件を満たし、証拠を `docs/evidence/` へ置いてから `complete` へ移します。方針、大きな設計の分かれ道、マージ、リリースは `awaiting approval` へ移し、選択肢、おすすめ、理由を添えます。

## ready

最初の一歩です。対象 OS は Linux で、クラウドエージェントの VM 上で進めます。 S01 と S02 と S03 は並行して着手できます。 S04 は、この 3 つが終わってからです。 S05 と S06 と S07 はその次です。 S08 が最後です。各タスクの検証は、その VM 上で、人の操作なしに実行できるコマンドです。

### S01 起動時間と描画 fps を記録する

状態は `ready` です。

先行するタスクはありません。

プロセス開始から最初のフレームまでを起動時間にします。描画の fps は、最初のフレームから 1 秒のあいだに出したフレーム数です。数値の良し悪しは、このタスクでは判断しません。目標値は、最初に動くものができてから Hayato が決めます。

受け入れ条件:

- 起動時間をミリ秒で `startup_ms` 、描画の fps を `fps` として、 `docs/evidence/metrics.jsonl` に 1 行ずつ残せます。
- テストが渡した `startup_ms` と `fps` が 1 行として書き出され、同じ数値で読み取れます。その自動テストが通ります。
- 検証は、クラウドの Linux VM 上で、人の操作なしに実行できるコマンドです。証拠はリポジトリに残ります。
- 完了報告に、テスト結果と、書き出した 1 行が付きます。

### S04 フィクスチャを GPUI のウィンドウへ表示する

状態は `ready` です。

先行は S01 と S02 と S03 です。

S03 のフレームを、 S02 のウィンドウの中に表示します。 Linux では CPU で画素をコピーして表示します。計測する起動時間と描画の fps は、このコピーを含んだ値です。

受け入れ条件:

- Linux で、フィクスチャの `susie-top` が GPUI のウィンドウの中に見えます。
- その画面のスクリーンショットが `docs/evidence/S04/` にあります。スクリーンショットは、クラウドの Linux VM 上のコマンドが自動で撮ります。
- このアプリを起動すると、 `docs/evidence/metrics.jsonl` に `startup_ms` と `fps` の新しい 1 行が自動で増えます。
- 表示経路は CPU コピーのままにします。別の経路へ変えるときは、タスクを `awaiting approval` にし、選択肢、おすすめ、理由を Hayato に出します。
- 検証は、クラウドの Linux VM 上で、人の操作なしに実行できるコマンドです。証拠はリポジトリに残ります。
- 完了報告に、スクリーンショットと、その起動の計測値が付きます。
